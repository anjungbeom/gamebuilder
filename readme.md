## 해커톤 핵심 조건

- 브라우저에서 설치 없이 바로 실행되는 웹 게임이어야 한다.
- 플레이 링크는 심사 기간 동안 승인 절차 없이 접근 가능해야 한다.
- 평가 항목은 Playability, Originality, Codex Collaboration, Release Potential, Presentation이다.
- 3분 이내 실제 플레이 영상과 Codex 활용 과정 설명은 선택 제출이며 가산점 대상이다.

## 게임 콘셉트

### 확정

- 비주얼: 도트 그래픽
- 중심 주제와 목적: 개척
- 세계: 계속 탐험할 수 있는 절차 생성 맵
- 생태계: 다양한 크리처가 절차적으로 생성되는 세계
- 핵심 장치: 플레이어가 화면에 직접 도구를 그리면 그것이 개척에 사용할 수 있는 도구가 된다.
- 참고 감성: `그려라, 터치!` 시리즈처럼 플레이어의 그림이 게임 속 상호작용 수단으로 이어진다.

### 권장 코어 루프

1. 미지의 영역을 탐색한다.
2. 지형이나 크리처 때문에 진행이 막힌다.
3. 필요한 도구를 직접 그린다.
4. 그림의 형태와 재료에 따라 도구의 성질이 결정된다.
5. 도구로 장애물을 해결하고 새로운 영역과 크리처를 발견한다.
6. 발견 기록과 자원을 쌓아 더 먼 곳을 개척한다.

## 절차 생성 알고리즘 후보

### 무한 맵

- **시드 기반 청크 생성**: 좌표와 월드 시드를 조합해 같은 장소가 항상 같은 모습으로 재생성되게 한다. 무한맵의 기반 구조로 가장 적합하다.
- **다중 옥타브 Perlin/Simplex 계열 노이즈**: 고도, 습도, 온도 값을 만들고 조합해 물·평야·숲·암석 등의 바이옴을 정한다.
- **Wave Function Collapse(WFC)**: 타일 인접 규칙을 이용해 유적, 마을, 동굴처럼 구조적 일관성이 필요한 관심 지점을 만든다.
- **Cellular Automata**: 동굴이나 군집 지형을 만드는 보조 알고리즘으로 사용할 수 있다.

초기 구현은 `시드 기반 청크 + 노이즈 바이옴`을 사용하고, WFC는 특별 지역에만 제한적으로 적용하는 방향을 권장한다. WFC만으로 끝없는 월드 전체를 만들면 청크 경계와 실패 복구가 복잡해질 수 있다.

### 무한 크리처

- **시드 기반 유전체(genome)**: 몸통, 부위 수, 대칭, 색상, 크기, 이동 방식, 성격을 숫자 유전자로 표현한다.
- **모듈형 문법/그래프 생성**: 몸통에 머리·다리·날개·꼬리 모듈을 규칙에 따라 붙여 실루엣을 만든다.
- **바이옴 적응 규칙**: 지형의 온도·습도·고도에 따라 생성 확률과 능력을 바꿔 생물이 환경에 적응한 것처럼 보이게 한다.
- **유전 알고리즘**: Karl Sims의 가상 크리처 연구처럼 변이와 선택으로 형태·행동을 진화시킬 수 있지만, 첫 프로토타입에는 계산량과 튜닝 부담이 크므로 후순위로 둔다.

초기 구현은 `유전체 + 모듈형 조립 + 바이옴 적응`으로 결정론적 크리처를 만들고, 실제 진화 시뮬레이션은 확장 기능으로 남기는 방향을 권장한다.

## 그리기 도구 시스템 후보

### 권장 방식: 형태의 수치가 기능을 결정

완성된 그림을 특정 사물 이름으로 맞히게 하기보다, 그림 자체의 기하 특성을 게임 수치로 변환한다.

- 긴 획: 사거리 또는 연결 거리 증가
- 넓고 닫힌 형태: 방어력 또는 부력 증가
- 뾰족한 끝: 절단력 또는 공격력 증가
- 갈라진 획: 갈고리, 집게, 채집 성능 증가
- 사용한 잉크 양: 무게와 내구도 증가

이 방식은 인식 실패로 플레이가 막히는 문제를 줄이고, 같은 목적에도 서로 다른 그림을 시도하게 만든다.

### 대안: 제스처 분류

도끼, 삽, 다리, 횃불처럼 정해진 도구를 인식해야 한다면 `$1/$P Recognizer` 같은 템플릿 기반 제스처 인식기를 사용할 수 있다. 구현은 가볍지만 플레이어가 정답 모양을 추측하게 되는 문제가 있으므로 템플릿 표시와 느슨한 판정이 필요하다.

## 독창성의 중심

무한 생성 자체보다 **플레이어가 그린 형태가 절차 생성 세계의 규칙에 대응하는 것**을 차별점으로 삼는다. 예를 들어 같은 그림이라도 사막에서는 삽, 늪에서는 뗏목, 설원에서는 썰매처럼 환경과 결합해 다른 쓰임을 갖게 할 수 있다.

## 미결 사항

- 시점: 탑다운, 횡스크롤, 쿼터뷰 중 무엇을 선택할지
- 도구가 이름으로 인식되는 방식인지, 형태의 물성이 그대로 반영되는 방식인지
- 플레이어의 최종 목표: 최대 개척 거리, 거점 확장, 생태 도감 완성, 특정 전설의 생물 발견 중 무엇인지
- 전투 비중과 크리처 관계: 사냥, 포획, 관찰, 교감 중 어디에 둘지
- 한 판의 길이와 실패·재도전 구조
