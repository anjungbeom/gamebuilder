# Codex와 함께 게임을 만든 과정

Drawn Frontier는 “그린 그림을 사물 이름으로 분류하지 않고, 획의 기하적 특징 자체를 게임 규칙으로 사용한다”는 사람이 정한 핵심 아이디어에서 시작했습니다. 플레이어가 긴 선, 뾰족한 꺾임, 닫힌 면, 여러 갈래를 그리면 각각 거리, 바위 파괴, 물길 횡단, 포획 성능으로 바뀝니다.

## Codex를 사용한 부분

Codex는 저장소 구조 조사, 기존 프로토타입 보존과 모듈 이전, 게임 시스템 구현, UI 문구 정리, 테스트 작성, Git 병합, GitHub Pages 배포까지 개발 전 과정의 협업 도구로 사용했습니다. 대화 중 결정된 요구를 작은 기능으로 그대로 붙이기보다 탐험→포획→획 수집→장비 제작→더 먼 개척이라는 하나의 성장 루프로 재구성했습니다.

구현한 주요 기능은 다음과 같습니다.

- 좌표와 시드만으로 재생성되는 무한 노이즈 바이옴과 화면 주변 청크 렌더링
- 유전체와 모듈형 몸 구조로 생성되는 절차적 크리처
- 그린 획의 길이, 각도, 폐곡선 넓이, 열린 끝 수를 측정하는 장비 분석기
- 손도구와 신발의 서로 다른 성능 기준 및 속도·내구성 트레이드오프
- Shift 달리기, 신발 마모, 체력, 도구 내구도와 피격 피드백
- 적대종과 평온종의 색·아이콘·행동 차이, 접촉 피해와 포획/관찰 보상
- 획 조각 인벤토리, Tab 장비 팔레트, 포획 마일스톤과 장비 보관칸 확장
- 8방향 캐릭터 실루엣, 방향 동기화 도구, 휘두르기 궤적
- 주변 바이옴 미니맵, 다음 맥점 방향과 거리, 다섯 맥점 목표
- 로컬 저장 호환성, 결정론적 월드/기하/브라우저 부팅 자동 테스트
- 테스트 성공 후에만 게시되는 GitHub Pages Actions 배포

## 해결한 문제

초기 프로토타입은 도구가 무엇을 하는지 수치 이름만으로 이해하기 어려웠고, 이동·발견·포획이 서로 보상으로 이어지지 않았습니다. Codex와 함께 능력치를 바위·거리·물길·포획처럼 결과 중심으로 바꾸고, 신발에는 질주·안정·수명을 따로 적용했습니다. 크리처 포획으로 얻은 획이 다음 장비 제작 비용이 되고, 포획 이정표가 장비 보관칸을 늘리도록 연결해 모든 시스템이 같은 개척 루프에 기여하게 했습니다.

무작위 월드 때문에 테스트 중 적대 크리처가 예상보다 일찍 플레이어를 공격하는 확률적 실패도 발견했습니다. 게임 동작을 제거하지 않고, 테스트가 “체력은 항상 최대치”라고 잘못 가정했던 부분을 유효 범위 검증으로 수정한 뒤 전체 테스트를 여러 시드에서 반복했습니다.

## 사람이 직접 결정한 부분

게임의 주제인 개척, 도트 그래픽, 직접 그리는 장비, 무한 맵과 크리처, 젤다식 자유 탐험, 크리처의 부위와 행동 제약, 장비 조작의 방향성은 개발자가 대화를 통해 직접 정했습니다. 또한 복잡한 자유 조작보다 읽기 쉬운 8방향 표현을 선택하고, 장비 슬롯을 손도구와 신발부터 시작하며, 보상을 새 지역 접근과 장비 제작으로 집중시키는 제품 판단도 개발자가 내렸습니다. Codex는 이 결정을 코드와 테스트 가능한 시스템으로 구체화하고 서로 충돌하는 요구를 정리하는 역할을 했습니다.
